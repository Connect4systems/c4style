## Differences and limits

- Shared styling is editable only by System Manager or Website Manager, as requested. Normal users control their own menu width, workspace width, direction and notes.
- Settings remain a native Single DocType rather than separate vendor Themes records.
- Group counts cover loaded rows only; this is not server-wide aggregation or a pivot report.
- Palette colors are independent approximations. Vendor code and branding are not included.
- Vendor-specific loading animations have not been reproduced. Note text/colors persist per account; pin visibility and window positions last for the page session.
- Native filters, saved filters, sorting, view selection, bulk actions and record permissions retain their Frappe behavior.

## Validation

Browser tests cover component styling, menus, RTL placement, mobile overflow, palette confirmation, launcher filtering, announcement escaping/dismissal, note saving, loaded-row grouping, drawer closing and scrolling. Backend tests cover roles, validated settings, note limits and account-specific persistence.

The image at `artifacts/reference-layout-preview.png` is a synthetic browser fixture generated by `python -B tests/render_reference_preview.py`, using real app assets and sample data. It is not a screenshot of the deployed server. Migration, layout and native Bootstrap behavior still require verification on the target Frappe installation.

## Follow-up on 23 October 2026

An authenticated regression run against oro.connect4systems.com used browser-local updated public assets with the existing deployed Python backend. All five native tabs opened and revealed their expected controls. All 17 presets persisted 19 colors each; all 15 component/menu choices saved and applied. Workspace navigation, hover expansion, notification/user drawers, announcement dismissal and 390px mobile overflow checks passed with no browser errors. Shared settings were restored exactly and verified after reload. See `artifacts/regression-review/report.json`.

The follow-up fixes the persistent menu's inner background overriding its palette, adds announcement colors to every preset, handles an unresolved startup route and delayed boot initialization, and provides a native reset-preset action. Python changes add preset defaults for palette-only API saves and missing document colors; those changes are covered locally and still require deployment before they can be verified on the server.

The video could not be fetched again because YouTube throttled the request. This follow-up uses the existing storyboard comparison above and the supplied settings screenshot, rather than claiming a new full-video review.


## Menu follow-up

The disabled legacy menu mode was reproduced on the deployed site. It used a native workspace sidebar about 90px from the viewport edge. The obsolete mode switch is now removed in favor of the consistent edge menu. Menu icon tokens and expanded-menu/header stacking were corrected. Short announcements no longer animate outside the visible strip; only overflowing text scrolls, with the text covering the viewport throughout the movement.

Read-only authenticated follow-up checks passed for the actual disabled legacy state, hover expansion and colors, all three notification categories, close/Escape handling, workspace/list/form placement and mobile overflow. Native notifications showed an empty state for the test account; notification delivery itself was not tested. See `artifacts/menu-review/report.json` and the complete field audit in `docs/settings-field-audit.md`.
